# ServicesOS Active Beta Planning

Status: Active planning  
Date: 2026-08-02  
Owner: Jamie Brown / Stellar Logic AI

## Purpose

This folder stores active ServicesOS beta planning decisions before they become coding tasks in `stellarlogicai/ServicesOS`.

The goal is to keep wife-beta planning focused, practical, and safe:

- ServicesOS remains the priority-one active build.
- Beta work should support real cleaning-business operations.
- Future platform features should be documented without distracting from beta-critical workflows.
- Coding agents should not turn design notes into implementation unless Jamie explicitly promotes them to a ServicesOS issue or Codex task.

## Current Wife-Beta Focus

The production application is live on the approved wife-beta release. Initial navigation feedback is positive: the application looks clean, navigation is easy, and feature locations are understandable.

The current execution route is:

```text
Complete one low-risk real cleaning job
→ record actual workflow friction
→ fix only beta-critical issues
→ repeat with another real job
→ implement the controlled multi-photo workflow
→ implement the focused GrowthAI Post Builder and server-enforced AI credits
```

The active owner workflow to validate is:

1. Dashboard
2. Add or select customer
3. Create estimate
4. Review and create booking
5. Calendar and job preparation
6. Field Mode and completion
7. Payment-status review

The beta should verify that these visible areas work through real cleaning-business use, not just that navigation looks clean.

## Current Market-Entry Focus

After wife beta blockers are fixed, ServicesOS should not launch broadly.

The next market-entry goal is:

```text
Get one real recurring cleaning customer to use ServicesOS,
keep using it after the first month,
and start proving ServicesOS can fund its own growth.
```

Current first external wedge:

```text
Small owner-operated cleaning businesses doing recurring residential cleaning,
move-out cleaning, real-estate prep cleaning,
and short-term rental turnover-style work.
```

## Important Rules

Route, crew, GPS, broad AI, payroll, employee app expansion, and job-costing design are important, but they should be implemented in controlled layers.

Do not overbuild advanced optimization, payroll processing, employee app scope, or autonomous AI before the basic owner workflow is stable.

The current work order is controlled wife beta first, then the multi-photo workflow, then the focused GrowthAI Post Builder with server-enforced AI credits. Cleaning-product restrictions may be promoted earlier as a separate safety task when real customer/property use requires it; they must not be combined with the multi-photo task. More advanced Schedule, Crew, Route Helper, AI Day Planner, Employee App, and Payroll Assist work remain separate future promoted tasks.

## Market-Entry Guardrail

Do not run paid ads, buy lead lists, build SMS automation, build broad AI at scale, or expand into other verticals before wife beta produces real workflow feedback and one narrow Founder Access test is ready.

Current rule:

```text
Real workflow first.
Wife beta second.
Focused photo and GrowthAI differentiation third.
Founder Access fourth.
Expansion later.
```
